# Assumptions

1. **Generic model only.** Keccak-256 is treated as a random oracle only for the explicitly labeled BHT and Grover projections. No structural-security, QROM Fiat–Shamir, MMCS-binding, composition, or protocol proof is inferred.
2. **Two-branch caveat.** Nominal 512/384/320 width is used in the generic arithmetic. Independence and combined binding of `K(0x00 || tag || payload)` and `K(0x01 || tag || payload)` have not been reduced to Keccak security. This assumption is not acceptance evidence.
3. **Multi-target convention.** `M = 2^m` counts security-relevant digest outputs over the protocol lifetime, not raw Keccak calls. The model projects BHT work as `2^((n-m)/3)` and Grover preimage/second-preimage work as `2^((n-m)/2)`, clamped at zero bits. Raw Keccak invocations are also reported as `M * branch_count`.
4. **Projection constants omitted.** Generic attack exponents omit algorithmic constants, circuit depth, fault tolerance, memory, parallelism cost, and oracle-construction cost. They are sensitivity projections, not achieved attacks or lower-bound theorems for these constructions.
5. **Unknown lifetime volume.** No production invocation forecast is accepted. The retained table sweeps `m = 0,16,24,32,40,48,56,64`; `run.py --target-log2 M` can replace or extend those points deterministically.
6. **Canonical frame.** `tag` is exactly one byte. A branch hashes `branch_u8 || tag_u8 || payload`, with branch bytes `0x00` and `0x01`. `payload` is already canonical raw bytes; no ABI offset, length, delimiter, or padding enters the hash.
7. **Truncation.** Solidity `bytes24(bytes32)` and `bytes20(bytes32)` semantics are used: retain the leftmost, most-significant 24 or 20 bytes of each branch. Branch zero precedes branch one. No cross-branch bit packing occurs.
8. **Authentication path.** A depth-20 binary path contains exactly 20 sibling digests. Raw path bytes exclude leaf, root, index, framing, ABI padding, and direction data. A separate 20-bit direction bitmap requires three bytes when minimally byte-aligned.
9. **Node payload.** The microbenchmark's binary-node payload is `left_digest || right_digest`, so its raw length is twice the digest width. The proof-node tag is `0x41`. This is a component benchmark input, not a claim that every application use has the same payload length.
10. **Storage layout.** Fixed digest storage is optimally represented in `ceil(width_bytes/32)` EVM slots with zeroed unused low-order suffix bytes. The harness measures cold untouched zero-to-nonzero slots; refunds, warm rewrites, mapping-key computation, and surrounding protocol state are outside scope.
11. **Gas boundary.** A Foundry row is an exact `gasleft()` delta for one low-level EVM call under solc 0.8.30, Prague, optimizer 200, via-IR. Deployment, transaction intrinsic gas, L1 calldata gas, and full verifier/pool behavior are excluded. No microbenchmark sum is a full-protocol estimate.
12. **Review state.** No independent cryptographer reviewed the 320- or 384-bit construction. Both remain `STOP_PENDING_EXTERNAL_ANALYSIS`. KeccakPair-512 remains frozen v0.3 baseline evidence but is not security-qualified by this study. Single-Keccak-256 is a deliberately nonqualifying lower bound.
